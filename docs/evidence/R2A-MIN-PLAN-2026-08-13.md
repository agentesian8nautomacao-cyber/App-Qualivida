- INSERT/UPDATE permanecem “qualquer authenticated” → **não** é exposição anônima; aperto = **REQUIRES M1/M12** (R2A.2)

**R2A-MIN não usa helpers** (`is_staff_from_auth` / `is_admin_for_staff_invites`). Isso evita segundo RBAC e o BLOCKED da R2A.1 (CABO_TURMA).

## Migration proposta (não executar)

Escopo **somente** Storage boletos:

1. `DROP POLICY "boletos_read_all"`
2. `CREATE POLICY "boletos_select_authenticated"` — SELECT **TO authenticated**, USING `bucket_id = 'boletos'`  
   - **Não** é RBAC / membership / helper  
   - É **restrição de role** da policy existente (public → authenticated), mesma condição de bucket  
   - Sem esta linha, download autenticado quebra; frontend signed URL **não** será alterado nesta etapa
3. `UPDATE storage.buckets SET public = false WHERE id = 'boletos'`
4. **Manter** insert/update autenticados intactos
5. **Não** alterar `packages`, helpers, outras tabelas, M1/M12

### O que NÃO entra

| Item | Motivo |
|------|--------|
| packages Allow all | Já **R1 PASS** |
| Trocar INSERT/UPDATE por helpers | R2A.1 BLOCKED; segundo RBAC |

| `site_id` / `condominium_id` no path | OWNERSHIP C; M1+ |

### Limitação residual (registrar, não “resolver”)

SELECT autenticado no bucket inteiro = **compatibilidade temporária — ownership pendente**. Qualquer sessão Auth que conheça o path lê o PDF. Isso **não** é isolamento tenant. Correção definitiva: **REQUIRES M1/M12**.
