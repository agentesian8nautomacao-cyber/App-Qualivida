============================================================
DECISÕES DR1–DR20
============================================================

DR1 — Identificador da confirmação
  CLOSED
  confirmation_id text PRIMARY KEY
  Formato compatível com API atual: cnf_ + hex (gerado na app)
  Não usar uuid separado + alias (evita dual-id)

DR2 — Token plaintext vs hash
  CLOSED
  Armazenar SOMENTE token_hash (SHA-256 hex)
  Plaintext confirmation_token retornado UMA VEZ na create
  Nunca logar plaintext em produção
  Preferência de segurança ATENDIDA

DR3 — Operações permitidas
  CLOSED
  pickup_package
  cancel_reservation
  Create rejeita outras ops (requiresConfirmation)

DR4 — Tenant boundary
  CLOSED
  organization_id uuid NOT NULL + condominium_id uuid NOT NULL
  FKs → organizations / condominiums
  Sem tenant_id genérico / sem fallback global

DR5 — Vinculação fingerprint
  CLOSED
  Coluna operation_fingerprint text NOT NULL
  Canônico:
    SHA-256("sentinela-confirm/v1\n" + org + "\n" + condo + "\n" + operation + "\n" + resource_id)
  Validate exige match
  ≠ Idempotency body fingerprint (G6-1)

DR6 — Expiração / TTL
  CLOSED
  Default 300 segundos (5 min)
  Clamp 30–3600 (já no serviço)
  Justificativa: janela curta para ação sensível; alinhado G4 testado
  Sem cron de purge nesta migration

DR7 — Uso único
  CLOSED
  status pending → consumed
  consumed_at NOT NULL quando consumed
  Reuso → CONFIRMATION_ALREADY_USED
  consumed_at mapeia used_at do TypeScript atual

DR8 — Concorrência
  CLOSED
  Consume via UPDATE … WHERE status='pending' AND consumed_at IS NULL
    AND expires_at > now() RETURNING
  No máximo uma execução bem-sucedida por confirmation_id
  PK impede rows duplicadas do mesmo id

DR9 — Estados
  CLOSED
  pending | consumed (text + CHECK)
  Expiração lógica por expires_at (sem status expired obrigatório)

DR10 — ON DELETE
  CLOSED
  FKs ON DELETE RESTRICT (padrão G6-1 / M3)

DR11 — Índices
  CLOSED (mínimos)
  PK confirmation_id
  idx_api_confirmations_expires_at
  idx_api_confirmations_tenant (organization_id, condominium_id)
  Sem índice de lookup por token_hash

DR12 — RLS
  CLOSED
  Fora de escopo da migration (não inventar policies)
  Fail-closed na API; service-role server-side
  Observação G6-1: plataforma pode habilitar relrowsecurity; 0 policies

DR13 — Trigger
  CLOSED — não utilizar

DR14 — Cron
  CLOSED — não utilizar nesta migration

DR15 — DML/seed
  CLOSED — zero INSERT/UPDATE/DELETE/seed/backfill na migration

DR16 — Rollback
  CLOSED
  DROP TABLE public.api_confirmations;
  sem CASCADE; falha se dependências inesperadas
  Limite: só após APPLY e se nenhuma FK externa apontar para a tabela

DR17 — Relação com G6-1
  CLOSED
  Não duplicar idempotência
  Confirmation = intenção sensível
  Idempotency = retry/mutação HTTP
  Ambos podem aplicar a SENSITIVE no wiring futuro

DR18 — Relação com n8n
  CLOSED
  n8n NÃO acessa banco
  Fluxo: n8n → API HMAC → confirmation endpoints/ops

DR19 — Segurança plaintext
  CLOSED
  Sem secret HMAC / confirmation_token / client secret na tabela
  prompt = texto operacional (não secret); minimizar PII em requester_identity

DR20 — Compatibilidade
  CLOSED
  G1–G5 contratos preservados
  G6-1 api_idempotency_keys intocada
  M1–M4 intocados
  Campos novos (fingerprint, consumed_at naming) exigem wiring alinhado —
  sem breaking do envelope HTTP de create/validate
