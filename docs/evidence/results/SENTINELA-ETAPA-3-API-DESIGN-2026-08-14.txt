4. OPERAÇÕES (1 endpoint → 1 Core)
============================================================
GET  /api/v1/residents/identify          → identify_resident

POST /api/v1/operations/packages         → create_package
POST /api/v1/operations/packages/{id}/pickup → pickup_package
POST /api/v1/operations/occurrences      → create_occurrence

GET  /api/v1/boletos                     → get_boleto

============================================================
5. CONTRATOS
============================================================
Sucesso/erro alinhados a OperationResult + request_id + correlation_id.
Códigos estáveis: TENANT_REQUIRED, UNAUTHORIZED, FORBIDDEN,
DUPLICATE_REQUEST, PACKAGE_ALREADY_PICKED_UP, RESERVATION_CONFLICT, etc.
HTTP: 400/401/403/404/409/429/500 conforme tabela no MD.

============================================================
6. AUTENTICAÇÃO
============================================================
Proposta: client_id + HMAC (timestamp + body hash + tenant + Idempotency-Key)
  + janela anti-replay + rotação de segredo.
Rejeitado: segredo fixo sozinho sem contexto.
JWT Supabase = opcional para caller humano futuro.
Service role NUNCA no n8n.

============================================================
7. AUTORIZAÇÃO
============================================================
Authn ≠ Authz.
Credential autenticada ainda precisa:
  tenant match + permission key da operação (RBAC existente).
Não criar segundo catálogo de permissões.
LIMITATION: memberships=0; grants de integração = DECISION REQUIRED.

9. IDEMPOTÊNCIA
============================================================
Idempotency-Key obrigatória em mutações (n8n usa wa_message_id estável).
request_id = por tentativa; correlation_id = conversa/fluxo.
Replay mesmo body → mesma resposta; body diferente → 409.

Store (Postgres/Redis/KV) = DECISION REQUIRED — NÃO criar tabela agora.
Memória de processo = inadequada no serverless.
